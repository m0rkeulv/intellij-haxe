### minor — src/main/java/com/intellij/plugins/haxe/runner/debugger/browser/BrowserTestRunHost.java:56
Three gaps in the orchestration loop. The `initialize` response at :56 is sent and discarded, unlike every other site in this branch (`BrowserDebugBackend.runParentHandshake` throws on `!isSuccess()`), so a rejected initialize is followed by a launch that can only hang. `pumpEvents` has no overall deadline: a page that 404s or throws before the reporter loads produces neither the sentinel nor a `TerminatedEvent`, and the run spins until the user presses Stop. And that Stop is itself misreported — `destroyProcessImpl` → `terminate` → `backend.close()` makes the in-flight `pollEvent` throw, which lands in the `catch (IOException)` at :60 and prints "The browser test run could not start: …" to stderr after the run has already ended. Check `isSuccess()`, bound the pump with a deadline, and skip the failure message when `finished` is already set.
