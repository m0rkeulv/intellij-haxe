### should-fix — src/test/java/com/intellij/plugins/haxe/HaxeCodeInsightFixtureTestCase.java:317
`toolAvailable` waits on the probe process without a timeout (`return process.waitFor() == 0;`) and leaves the child's stdin as an open pipe. `haxelib path <lib>` can block on a prompt (install/update confirmation) with nobody reading or writing that pipe, and the whole suite then hangs instead of skipping — exactly the failure mode the gates exist to avoid. The sibling probe in the same repo does it right (`LiveProbeUtil.haxeOnPath`: `probe.waitFor(10, TimeUnit.SECONDS) && probe.exitValue() == 0`). Use a bounded `waitFor(timeout, unit)` (plus `destroyForcibly()` on expiry) and treat expiry as "not available".

### should-fix — src/test/java/com/intellij/plugins/haxe/v2/buildtools/NmeProjectsTest.java:63
The new assertion computes its condition inline and carries an uncommented regex: `assertTrue(artifact.relativeOutput().matches("bin/(windows|mac64|linux64)-neko/MyGame/MyGame(\\.exe)?"), artifact.relativeOutput());`. That breaks two rules at once — "an assertion's condition states a fact, it does not compute one" (the assert wraps onto a second line), and "every regex carries a comment above it saying what it matches". Extract a named local with the comment above it, e.g. `// bin/<host>-neko/<app>/<app>[.exe] - nme names the folder after the BUILD host` / `boolean hostSuffixedLauncher = artifact.relativeOutput().matches(...);` then `assertTrue(hostSuffixedLauncher, artifact.relativeOutput());`.

### should-fix — src/test/java/com/intellij/plugins/haxe/haxelib/HaxelibLocalDocsTest.java:93
`Files.writeString(versionDir.resolve("readme.MD".toLowerCase()), "readme");` — the `.toLowerCase()` on a string literal is a no-op that just yields `"readme.md"`, and it silently cancels the coverage the test's own display name promises ("...regardless of case"): the readme fixture ends up all-lowercase, so only `CHANGELOG.md`/`LICENSE` exercise `matchesBaseName`'s case folding.
